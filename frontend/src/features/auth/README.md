# 회원 인증·접근 권한

계획서: SFR-001

Google OAuth 로그인과 사용자 식별·역할. 개인 자료 소유권은 해당 매물·방문 유스케이스에서도 검증한다.

현재 `pages/AuthPage.jsx`는 일반 로그인·회원가입 입력 화면을 제공한다. 회원가입은 형식과 비밀번호 확인만 검증한다. local 모드에서는 아래 가상 계정으로 화면 상태를 전환할 수 있다. 실제 회원 저장·서버 인증·Google 연동은 이후 구현한다.

| 구분 | 아이디 | 비밀번호 |
|---|---|---|
| 관리자 시연 | `admin` | `admin1234` |
| 일반 사용자 시연 | `user` | `user1234` |

`model/demoAccounts.js`에 공개 가상 계정을 두고 `model/useDemoAuth.js`에서 시연 상태만 관리한다. 같은 탭의 새로고침을 위해 sessionStorage에 계정 ID만 저장하며 비밀번호·역할을 저장하지 않는다. 로그아웃하면 해당 값을 지운다. api 모드에서는 시연 계정을 사용하지 않는다.

관리자 표시는 UI 역할 확인용이며 서버의 관리자 권한을 만들지 않는다. 별도 관리 화면은 아직 없다. 두 계정은 기존 브라우저 매물 데이터를 공유하므로 실제 사용자별 자료 격리 시험으로 사용하지 않는다.

화면은 `pages/`, 해당 기능의 UI는 `components/`, React에 의존하지 않는 화면 계산은 `domain/`, 기능 상태는 필요할 때 `model/`에 둡니다. 서버 요청은 앱에서 주입한 저장소를 통해 수행합니다. 현재 없는 하위 폴더와 기능은 구현할 때 추가합니다.

서버 규칙과 연결: `backend/src/main/java/com/roomcrosscheck/auth/` (저장소 루트 기준).
