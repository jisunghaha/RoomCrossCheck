# 광고 등록 오류와 동시 재요청

첨부 일정표의 SFR-002(매물 광고 등록)를 현재 기능 브랜치에서 보완한다. 회원 인증, OCR 모델 개선, 팀 DB 전환, 다른 브랜치 병합은 포함하지 않는다.

## 사용자 동작

- 10MB 초과 이미지는 전송 전에 안내한다. 서버의 파일 10MB·요청 11MB 제한도 유지한다.
- 잘못된 확장자·MIME·실제 이미지 내용, 입력 길이, 빈 원본의 거절 사유를 안내한다.
- 오류 응답이 JSON이 아니어도 상태별 기본 안내를 제공한다. 서버 내부 오류 본문은 화면에 노출하지 않는다.
- 전송 실패 시 글·첨부 선택·요청 키를 유지한다. 입력을 수정하면 새 키를 사용한다.

## 서버 재요청 처리

같은 Idempotency-Key가 이미 있으면 요청 내용의 SHA-256을 비교한다. 내용이 같으면 기존 광고를 반환하고, 다르면 409로 거절한다. HTTP 생성 응답은 기존 계약인 201을 유지하며 재요청도 같은 ID를 반환한다.

동시 최초 요청은 DB UNIQUE 제약으로 한 건만 저장한다. saveAndFlush의 repository 트랜잭션이 종료된 뒤 제약 위반을 처리하고, 별도 조회에서 성공한 요청을 확인한다. 이 서비스 생성 메서드에 외부 트랜잭션을 추가하면 실패한 트랜잭션 안에서 재조회하지 않도록 경계를 다시 설계해야 한다.

실패한 요청이 만든 이미지 파일은 제거하며 성공한 요청의 파일은 보존한다. 키에 해당하는 기존 광고가 없으면 다른 무결성 오류를 성공으로 바꾸지 않고 그대로 실패시킨다. DB 스키마는 변경하지 않는다.

이 재요청 처리는 광고 원본 생성에 대한 것이다. 기존의 최종 매물 등록 중복 방지와는 별개이며, 최종 매물 연결의 잠금·UNIQUE·FK는 유지한다.
