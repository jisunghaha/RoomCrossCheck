# 항목별 AI 추출 근거

첨부 일정표 SFR-004의 항목별 근거·불명확 여부를 현재 기능 브랜치에서 보완한다. 새로운 OCR 엔진·인증·팀 DB 전환은 포함하지 않는다.

## 저장 계약

ExtractionResult의 선택 evidence 객체를 기존 extractionJson에 보관한다. DB 컬럼은 추가하지 않는다. 키는 address·depositWon·monthlyRentWon·maintenanceFeeWon·areaSqm·floor·areaType·options의 8개만 허용한다. 각 항목은 quote(최대 500자), source, status, reason(최대 200자)을 갖는다.

- source: INPUT_TEXT(보관된 광고 글) 또는 IMAGE_READ_TEXT(AI가 읽은 이미지 글).
- status: PRESENT(근거 문구 있음), NOT_STATED(AI 판단: 미기재), UNCERTAIN(확인 필요).
- 광고에 없는 값·불명확한 값은 null, 면적 종류는 미상으로 반환하도록 요청한다. null과 0, 옵션 미확인과 명시적 옵션 없음의 기존 의미를 유지한다.

메타데이터가 없는 구버전 응답·저장 JSON은 계속 읽으며 화면에는 근거 기록 없음으로 표시한다. 과거 데이터에서 근거를 임의 생성하거나 일괄 변환하지 않는다. 일부 항목의 근거가 생략된 경우에도 미기재로 추측하지 않고 기록 없음으로 표시한다.

## 검증과 한계

quote는 지정한 참조 글에 정확히 포함돼야 한다. IMAGE_READ_TEXT는 실제 이미지 첨부가 있어야 사용할 수 있다. 주소·동호수 힌트는 근거로 검증하지 않는다. 일치하지 않는 문구는 제거하고 UNCERTAIN과 서버 안내로 바꾼다. PRESENT인데 값이 없거나 NOT_STATED인데 값이 있으면 같은 방식으로 낮춘다. 미상 면적 종류는 값 없음으로 다루며 명시적 0과 빈 옵션 배열은 값이 있는 것으로 다룬다.

UNCERTAIN에 근거 문구가 없으면 제한 길이의 AI 설명만 보존할 수 있다. 잘못된 항목 키·자료형·상태·출처·길이는 응답 오류로 거절한다. 수치 신뢰도는 만들지 않는다.

이 검증은 문구 포함 여부와 상태 관계만 확인한다. 인용 문구와 수치의 의미가 맞는지, AI가 읽은 글이 원본 이미지와 같은지, 실제 매물이 광고대로인지는 보증하지 않는다. 화면에서 이 한계를 안내하며 사용자가 원본을 대조해야 한다. 근거 검증 실패 시 AI 후보 값을 임의 변경하지 않고 확인 필요로 표시한다.

## 사용자 확인

확인 폼에 최초 AI 값·근거 문구·참조 글·상태·안내를 읽기 전용 표로 표시한다. 보관된 글과 최초 AI가 읽은 글도 구분한다. 수정 입력과 저장 흐름은 유지한다.

사용자 확인 요청에서 전달한 evidence는 저장하지 않는다. reviewedJson에는 수정값만 보관하고 최초 extractionJson의 값·글·근거는 그대로 유지한다. 이 작업은 사용자 수정 이력·버전 또는 저장 충돌 제어를 구현한 것이 아니다.

## 검증 기록 (2026-11-04)

백엔드 40건·프론트 53건·실행 설정 6건과 Java clean package·프론트 빌드를 통과했다. 단위 테스트에서 참조 글·첨부 구분, 없는 문구·상태 모순의 확인 필요 처리, JSON 호환성·길이 제한, 사용자 근거 위조 방지를 확인했다.

격리 MySQL 8.4와 로컬 공급자에서 글·이미지 읽은 글의 근거·미기재·면적 종류 불명확 상태를 저장했다. 최초 AI 월세 350000과 사용자 수정 380000→390000을 분리하고 AI JSON이 바뀌지 않는지 확인했다. 잘못된 숫자형 근거·길이 초과·알 수 없는 필드는 502로 거절하며 재시도를 지원했다. 구버전 JSON과 새 근거·수정값의 재조회·재시작 보존을 검증했다.

Chromium에서 근거 표·확인 상태·수정 저장·새로고침 후 보존을 확인했다. 검증 중 설명을 포함한 표 셀과 저장 후 변경된 입력값에 맞춰 자동화 선택자를 보정했다. 실제 Gemini 호출은 0건이며 로컬 모형의 응답은 AI 정확도 검증 근거로 계산하지 않는다. 임시 DB·첨부는 정리했다.
