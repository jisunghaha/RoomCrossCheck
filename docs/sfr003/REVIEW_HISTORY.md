# SFR-005 확인값 수정·이력·충돌 방지

2026-11-06, `feature/sfr-003-gemini-extraction`의 로컬 개발용 광고 API에 적용한다.
최초 AI 추출값·근거, 광고 확인값, 최종 매물 폼 값은 계속 별개다.

## 저장 계약

광고 응답에 `reviewVersion` 정수가 추가된다. 기존 광고와 아직 확인하지 않은 광고는 0이다.
`PUT /api/advertisements/{id}/extraction`의 본문은 기존 확인값 JSON과 같으며,
조회한 광고의 버전을 `X-Review-Version` 헤더로 반드시 전달한다.
서버가 광고 행을 잠근 뒤 버전을 비교하고, 확인값 갱신·버전 증가·이력 추가를 같은 트랜잭션으로 처리한다.
최종 매물 등록도 기존에 같은 광고 행 잠금을 사용한다.

- 헤더 누락: 428. 프론트와 서버를 함께 갱신해야 하며, 이전 클라이언트의 무조건 저장은 허용하지 않는다.
- 잘못된 헤더 형식·음수 버전·잘못된 확인값: 400.
- 이전 버전 또는 저장 제약 충돌: 409. 확인값과 이력은 변경하지 않는다.
- 잠금 획득 실패: 503. 내부 SQL·제약 이름은 응답에 포함하지 않는다.
- 성공: 확인값이 담긴 광고와 증가한 버전을 반환한다. 서버 응답으로 해당 폼만 갱신한다.

AI의 `extractionJson`은 변경하지 않고, 확인 요청의 `evidence`는 버린다.
`advertisement_reviews`에 버전별 확인값 전체와 저장 시각을 추가한다.
별도 수정·삭제·자동 복원 API는 제공하지 않는다. 같은 값을 다시 확인 저장해도 새 버전으로 기록한다.

## 이력 조회와 기존 데이터

`GET /api/advertisements/{id}/reviews`는 최근 최대 20건을 버전 내림차순으로 반환한다.
각 항목은 `{version, reviewedAt, reviewed}`이다. DB에는 그 이전 이력도 보존한다.
없는 광고는 404이고, 아직 이력이 없는 광고는 빈 배열이다.

이력 도입 전에 저장한 광고는 일괄 수정하지 않는다. 처음 다시 저장할 때 기존 마지막 확인값을
버전 0으로 보존하고 새 값을 버전 1로 남긴다. 과거에 이미 덮어쓴 값이나 알 수 없는 시각은 복원하지 않는다.
화면의 '수정 이력 보기'에서 저장 버전·시각·각 확인값을 조회한다. 자동 변경 강조는 포함하지 않는다.

## 미저장 변경 보호

확인 폼이 최초 표시값과 다르면 안내하고, 저장 중에는 확인 폼 입력을 막는다.
원래 값으로 돌리면 변경 표시를 해제한다. 옵션의 미확인/null, 없음/빈 배열 구분도 유지한다.
광고 확인 폼에 미저장 변경이 있으면 다음을 적용한다.

- '확인한 값으로 매물 등록' 비활성화: 저장된 이전 값으로 잘못 넘어가는 것을 막는다.
- 앱 메뉴·목록 이동·등록 방식 변경 시 이동 확인. 취소하면 입력을 유지한다.
- 새로고침·창 닫기는 브라우저 기본 미저장 경고를 요청한다. 표시 여부·문구는 브라우저 정책에 따른다.
- 저장 실패·버전 충돌 시 입력 유지. '최신값 불러오기'는 변경 폐기 확인 후 해당 광고만 다시 읽는다.

이 보호는 광고 확인 폼에 적용한다. 직접 입력 등록 폼·최종 매물 폼 전체의 초안 자동 저장,
모바일 브라우저 강제 종료 복구는 별도 범위다. 브라우저 뒤로 가기 취소 시 현재 경로로 복구하지만
브라우저 방문 기록 순서까지 재구성하지 않는다.

## DB 적용 범위

개발용 `advertisements.review_version`과 `advertisement_reviews` 테이블을 추가한다.
새 임시 DB는 기존 JPA update 설정을 따른다. 기존 데이터가 있는 DB는 앱 실행 전에
[SQL 적용 안내](sql/README.md)의 대상 확인·백업·컬럼/테이블 확인을 먼저 수행한다.
팀 `rooms`·Flyway V1·인증·다른 브랜치와 공유 DB는 변경하지 않는다.
인증 통합 전의 로컬 개발 API이므로 실제 작성자를 기록했다고 표시하거나 임의 사용자 ID를 저장하지 않는다.
운영 전에는 인증·소유권과 이력 열람 권한·개인정보 보존/삭제 정책을 함께 연결해야 한다.
이력 보존은 변경 감사를 위한 변조 방지 시스템이나 전체 추출 작업의 분산 잠금을 의미하지 않는다.

## 검증

프론트 테스트는 미저장 변경·이동 취소·오래된 저장 실패·명시적 최신값 불러오기·새 버전 재저장·이력 표시를 확인한다.
백엔드 테스트는 버전 누락·불일치 시 무변경, 기존 마지막 확인값 보존, 최초 AI 근거 보존을 확인한다.
검증 결과: 프론트 58건·백엔드 42건·런타임 6건 통과, Vite 빌드와 Maven clean package 성공.
별도 실제 MySQL에서 기존 스키마에 SQL을 적용한 뒤 기존 광고의 원본·추출값·확인값 보존을 확인했다.
동일 버전의 동시 요청 8개 중 1개만 200이고 7개는 409였으며 새 이력도 1건만 추가됐다.
이력 INSERT를 강제로 실패시킨 경우 확인값·버전이 롤백됐고, 서버 재시작 후 값과 이력을 다시 조회했다.
Chromium 두 화면에서 저장 충돌·입력 보존·이동 취소·명시적 최신값 불러오기·새 버전 저장·이력 조회·새로고침·등록 방식 전환을 확인했다.
검증 화면에는 버전 4·3·2·1·기존 마지막 값 0이 표시됐으며 JavaScript 오류는 없었다.
다른 광고 업로드 후 목록 갱신이 미저장 폼과 기존 버전을 보존하는 회귀 테스트도 포함했다.
검증용 임시 MySQL 컨테이너·볼륨과 서버·프론트 프로세스는 정리했다. 외부 Gemini 생성 요청은 0건이다.
작성자 식별·인증 연동·공유 DB·운영 부하·대표 OCR 정확도는 이번 검증 범위가 아니다.
